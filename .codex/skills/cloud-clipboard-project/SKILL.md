# Cloud Clipboard Project

Work from the repository root. Treat `README.md`, `wrangler.jsonc`, migrations, and source as the current truth; treat this Skill as operational routing and guardrails.

## Start every task

1. Run `git status -sb` and preserve unrelated user changes.
2. Read the relevant source files completely before editing.
3. Read one reference based on the task:
   - Architecture or feature work: `references/architecture.md`
   - Cloudflare setup, deploy, production checks, or incidents: `references/operations.md`
   - API, D1, retention, or storage work: `references/data-and-api.md`
4. Load the Cloudflare Workers and Wrangler platform skills before changing Worker code or running Wrangler commands.
5. Retrieve current Cloudflare documentation before relying on command syntax, limits, configuration fields, or R2 behavior.

## Non-negotiable boundaries

- Keep the whole production hostname behind Cloudflare Access. Never bypass Access to make testing easier.
- Keep R2 private. Use short-lived presigned URLs; never expose credentials to the browser.
- Never print, read back, commit, or request secrets in chat. Use `wrangler secret put` and verify names with `wrangler secret list`.
- Never commit `.dev.vars`, `.env`, `.wrangler`, `dist`, `node_modules`, or test payloads.
- Do not log clipboard text, presigned URLs, Access tokens, or file contents.
- Preserve the default 24-hour retention unless the user explicitly changes product requirements.
- Treat R2 lifecycle expiry as the final file-deletion guarantee; application cleanup is supplementary.
- Do not describe the product as end-to-end encrypted.

## Implementation map

- `src/App.tsx`: UI state, clipboard debounce, upload progress, history, theme toggle.
- `src/api.ts`: browser API client and XHR upload progress.
- `src/styles.css`, `src/history.css`, `src/theme.css`: layout and themes.
- `worker/index.ts`: API routing, D1 access, R2 signing, completion checks, cleanup.
- `migrations/`: append-only D1 schema changes.
- `wrangler.jsonc`: bindings, assets, compatibility date, observability, non-secret vars.
- `cloudflare/r2-cors.example.json`: tracked template; keep the deployed `cloudflare/r2-cors.json` local and untracked.
- `worker-configuration.d.ts`: generated by `npm run cf:types`; do not hand-edit except mechanical formatting after generation.

## Change workflow

1. Make the smallest coherent change.
2. Run `npm run cf:types` after changing `wrangler.jsonc`.
3. Run `npm run typecheck` and `npm run build`.
4. For UI work, run `npm run cf:dev` and inspect desktop and mobile layouts in a real browser.
5. For database changes, add a new numbered migration; never rewrite an applied production migration.
6. For production changes, verify Access before using test data, then use only non-sensitive test content.
7. Inspect `git diff --check` and staged scope before committing.
8. Commit tersely and push `main` only when the user authorizes publication.

## Definition of done

- Typecheck and production build pass.
- No secret or local state is staged.
- UI remains usable at mobile and desktop widths when UI changed.
- Anonymous production access redirects to Cloudflare Access.
- Clipboard and file metadata remain filtered by expiry.
- Uploads reach `ready` only after R2 `HEAD` size verification.
- Documentation and CORS origins match deployment changes.
